### 性能基准

| 步骤 | 预期耗时 | 如果超时可能原因 |
|------|---------|----------------|
| 获取UID列表 | 0.1-0.3秒 | 网络慢或服务器慢 |
| 获取50封邮件头 | 4-8秒 | 网络慢,每封100-150ms |
| 保存到Store | 0.02-0.1秒 | 内存操作,应该很快 |
| 后台写数据库 | 0.1-0.5秒 | 不影响UI |
| **总UI等待时间** | **4-9秒** | 主要是网络请求 |

## 🐛 可能的瓶颈

### 1. 获取邮件头太慢 (每封>200ms)

**原因**: 
- 网络延迟高
- 服务器响应慢
- LibEtPan每次获取邮件头都是独立请求

**优化方案**:
```objc
// 批量获取邮件头 (一次请求获取多封)
// TODO: 实现批量FETCH ENVELOPE
```

### 2. 仍然在主线程等待

**检查**: 如果日志显示"同步完成"后UI才响应,说明Task没有真正后台执行

**验证方法**:
```swift
// 在selectFolder开始处打印
print("🎯 当前线程: \(Thread.isMainThread ? "主线程" : "后台线程")")
```

### 3. 数据库写入慢

**检查**: 如果"保存完成"耗时>0.5秒,说明数据库操作有问题

**可能原因**:
- 没有索引
- 事务太大
- 磁盘IO慢

    }

### 优化3: 使用虚拟列表

如果邮件列表很长,考虑使用 LazyVStack:
```swift
ScrollView {
    LazyVStack {  // 只渲染可见部分
        ForEach(messages) { message in
            MessageRow(message: message)
        }
    }
}
```
