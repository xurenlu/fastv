# 视频并行处理时长增加问题修复说明

## 问题描述

用户反馈：使用并行处理模式处理视频后，输出视频的时长比原视频增加了约 3 秒。

## 问题原因分析

视频时长增加的问题通常由以下几个原因导致：

### 1. **时间戳不连续问题**
当使用 `concat` demuxer 合并视频片段时，如果各片段之间的时间戳不连续，FFmpeg 可能会：
- 在片段之间插入黑帧来填补时间戳间隙
- 延长最后一帧的显示时间
- 添加额外的音频静音段

### 2. **关键帧对齐问题**
使用 `-c copy` 模式切分视频时：
- 如果切分点不在关键帧（I-frame）位置，FFmpeg 会从最近的关键帧开始复制
- 这可能导致片段的实际起始时间早于指定时间
- 多个片段累积后，总时长会增加

### 3. **音视频同步问题**
- 视频流和音频流的时长可能略有不同
- 合并时 FFmpeg 会以较长的流为准，导致总时长增加

### 4. **`avoid_negative_ts` 参数问题**
- 之前使用 `-avoid_negative_ts 1`（make_non_negative）模式
- 这种模式会移动所有时间戳以避免负值，可能导致时长增加
- 更好的选择是 `make_zero` 模式，将时间戳重置为从 0 开始

## 修复方案

### 1. 改进切分视频函数 (`splitVideo`)

**修改前：**
```bash
ffmpeg -y -ss <start> -t <duration> -i <input> -c copy -avoid_negative_ts 1 <output>
```

**修改后：**
```bash
ffmpeg -y -ss <start> -i <input> -t <duration> -c copy \
  -avoid_negative_ts make_zero \
  -fflags +genpts \
  <output>
```

**改进点：**
- 将 `-ss` 参数移到 `-i` 之前，实现输入端精确定位（更快，更准确）
- 使用 `-avoid_negative_ts make_zero` 重置时间戳为从 0 开始
- 添加 `-fflags +genpts` 重新生成 PTS（Presentation Time Stamp）
- 添加时长验证日志，及时发现问题

### 2. 改进合并视频函数 (`mergeSegments`)

**修改前：**
```bash
ffmpeg -y -f concat -safe 0 -i <concat_list> -c copy <output>
```

**修改后：**
```bash
ffmpeg -y -f concat -safe 0 -i <concat_list> \
  -fflags +genpts \
  -c copy \
  -avoid_negative_ts make_zero \
  <output>
```

**改进点：**
- 添加 `-fflags +genpts` 重新生成时间戳，确保连续性
- 使用 `-avoid_negative_ts make_zero` 避免时间戳偏移
- 添加预期时长和实际时长的对比日志
- 当时长差异超过 1 秒时发出警告

### 3. 添加详细的时长验证日志

**切分阶段：**
```
✂️ [VideoSegmentProcessor] 切分片段 0: 0.00s - 30.00s
   实际时长: 30.12s, 预期: 30.00s, 差异: 0.120s
```

**合并阶段：**
```
📊 [VideoSegmentProcessor] 预期总时长: 120.00秒
🔗 [VideoSegmentProcessor] 合并完成
📊 [VideoSegmentProcessor] 实际时长: 120.15秒
📊 [VideoSegmentProcessor] 时长差异: 0.15秒
```

**警告提示：**
```
⚠️ [VideoSegmentProcessor] 警告：合并后视频时长与预期不符！差异: 3.20秒
```

## 预期效果

修复后，视频时长的差异应该控制在：
- **正常情况**：< 0.5 秒（由于关键帧间隔导致的正常偏差）
- **可接受范围**：< 1.0 秒
- **需要警告**：> 1.0 秒

## 如何验证修复效果

1. **查看日志输出**：
   - 检查每个片段的时长差异
   - 检查最终合并后的时长差异
   - 注意是否有警告信息

2. **手动验证**：
   ```bash
   # 查看原视频时长
   ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 input.mp4
   
   # 查看处理后视频时长
   ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 output.mp4
   ```

3. **对比播放**：
   - 在播放器中同时打开原视频和处理后的视频
   - 对比总时长显示
   - 检查视频结尾是否有多余的黑屏或静音

## 其他建议

### 1. 如果问题仍然存在

如果修复后时长差异仍然 > 1 秒，可以尝试：

**方案 A：使用重新编码模式合并**
```bash
# 在 mergeSegments 中使用
-c:v libx264 -preset ultrafast -crf 18 -c:a aac
```
优点：时长更准确
缺点：速度较慢，会有轻微的质量损失

**方案 B：调整分段时长**
- 增加 `segmentDuration`（如从 30 秒改为 60 秒）
- 减少片段数量可以减少累积误差

**方案 C：在关键帧处切分**
```bash
# 添加 -force_key_frames 参数
-force_key_frames "expr:gte(t,n_forced*30)"
```

### 2. 性能优化建议

- 对于短视频（< 60 秒），建议关闭并行处理
- 对于长视频（> 300 秒），可以适当增加 `segmentDuration` 到 60-90 秒
- 根据 CPU 核心数调整 `maxConcurrentTasks`
