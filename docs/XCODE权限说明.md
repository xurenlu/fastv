# Xcode 中运行时的权限说明

## ✅ 权限配置状态

项目已正确配置所有必需的权限：

1. **麦克风权限** (`NSMicrophoneUsageDescription`)
   - ✅ 已在 `Info.plist` 中配置
   - ✅ 已在 `project.pbxproj` 中配置
   - ✅ 用途描述：`FastV 需要访问您的麦克风以进行语音输入和语音转文字功能。`

2. **辅助功能权限** (`NSAppleEventsUsageDescription`)
   - ✅ 已在 `Info.plist` 中配置
   - ✅ 已在 `project.pbxproj` 中配置
   - ✅ 用途描述：`FastV 需要辅助功能权限以监听全局快捷键、访问剪贴板并自动将识别文本插入到其他应用的输入框中。`

## 🔧 在 Xcode 中运行时的权限行为

### 1. 麦克风权限

**首次运行：**
- 应用启动时会自动请求麦克风权限
- 系统会弹出权限请求对话框
- **点击"好"即可授权**

**如果权限被拒绝：**
- 可以在设置界面点击"申请权限"按钮重新请求
- 或者手动在"系统设置 > 隐私与安全性 > 麦克风"中找到 `fastv` 并勾选

**检查权限状态：**
- 打开应用设置界面 → 语音输入法 → 权限状态
- 查看控制台日志（会打印权限状态）

### 2. 辅助功能权限

**首次启用语音输入：**
- 代码会自动请求辅助功能权限
- 系统会弹出权限请求对话框
- **点击"打开系统偏好设置"**
- 在"系统设置 > 隐私与安全性 > 辅助功能"中找到 `fastv` 并勾选

**重要提示：**
- 辅助功能权限**必须手动在系统设置中授权**
- 这是 macOS 的安全机制，无法通过代码自动授权
- 没有此权限，全局快捷键监听和文本插入功能将无法工作

**检查权限状态：**
- 打开应用设置界面 → 语音输入法 → 权限状态
- 查看控制台日志（会打印权限状态）

## 📋 权限授权步骤

### 方法一：通过应用设置界面

1. 运行应用
2. 打开设置（点击工具栏的设置按钮）
3. 进入"语音输入法"部分
4. 查看"权限状态"
5. 点击"申请权限"或"打开设置"按钮

### 方法二：通过系统设置

**麦克风权限：**
1. 打开"系统设置"
2. 进入"隐私与安全性"
3. 选择"麦克风"
4. 找到 `fastv` 并勾选

**辅助功能权限：**
1. 打开"系统设置"
2. 进入"隐私与安全性"
3. 选择"辅助功能"
4. 找到 `fastv` 并勾选

## 🔍 调试权限问题

### 查看控制台日志

在 Xcode 中运行时，控制台会打印详细的权限状态信息：

```
🎤 [fastvApp] 当前麦克风权限状态: 0
🎤 [fastvApp] 权限未确定，请求麦克风权限...
💡 [fastvApp] 提示：系统将弹出权限请求对话框，请点击'好'授权
✅ [fastvApp] 麦克风权限已授权

🔧 [GlobalShortcutMonitor] 辅助功能权限状态: 已授权
```

### 权限状态值说明

**麦克风权限状态：**
- `0` = `.notDetermined` - 未确定（首次使用）
- `1` = `.restricted` - 受限
- `2` = `.denied` - 被拒绝
- `3` = `.authorized` - 已授权

**辅助功能权限：**
- `true` = 已授权
- `false` = 未授权

## ⚠️ 常见问题

### Q: 为什么在系统设置的麦克风权限列表中没有看到 fastv？

**A:** 可能的原因：
1. 应用还没有尝试请求麦克风权限（首次启动时才会请求）
2. 权限请求对话框被忽略了
3. 应用没有正确签名

**解决方法：**
- 在应用设置界面点击"申请权限"按钮
- 或者尝试使用语音输入功能（会自动触发权限请求）

### Q: 辅助功能权限为什么必须手动授权？

**A:** 这是 macOS 的安全机制。辅助功能权限允许应用：
- 监听全局键盘事件
- 模拟键盘输入
- 访问其他应用

这些操作涉及系统安全，因此必须用户手动在系统设置中授权。

### Q: 在 Xcode 中运行时权限是否有效？

**A:** 是的！在 Xcode 中运行时：
- ✅ 应用有开发签名（Development Team）
- ✅ 权限请求对话框会正常弹出
- ✅ 授权后权限会正常生效
- ✅ 权限状态会保存到系统设置中

**注意：** 每次重新编译运行，如果应用 Bundle ID 相同，权限状态会保留。

## 📝 开发建议

1. **首次运行：** 确保在应用启动时查看控制台日志，了解权限请求流程
2. **测试权限：** 尝试拒绝权限，然后通过设置界面重新申请
3. **权限状态：** 在设置界面实时查看权限状态，确保功能正常
4. **日志调试：** 使用控制台日志排查权限相关问题
