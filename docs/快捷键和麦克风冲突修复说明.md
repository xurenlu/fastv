# 快捷键和麦克风冲突修复说明

## 问题描述

### 1. FN键释放检测延迟问题
**现象**：按下FN键后悬浮条出现，但松开FN键后，悬浮条没有立即转到转录文字阶段。

**原因**：FN键在macOS上的行为特殊，不会产生标准的keyUp事件，之前的实现使用了150ms的超时检测机制，导致释放检测延迟。

### 2. 与闪电说等应用的冲突
**现象**：当闪电说和本应用都使用FN键作为快捷键时，会产生冲突。

**原因**：
- 两个应用都监听同一个快捷键（FN键）
- 麦克风资源是独占的，同时只能被一个应用使用
- 哪个应用先抢到麦克风，另一个就会失败

## 解决方案

### 1. 改进FN键释放检测机制

**文件**：`fastv/Services/GlobalShortcutMonitor.swift`

**改进内容**：
- 将超时检测间隔从150ms缩短到50ms
- 将定时器检测间隔从50ms缩短到20ms
- 移除延迟检查，立即触发释放事件
- 优化flagsChanged事件的处理逻辑

**代码变更**：
```swift
// 之前：超时时间150ms，检测间隔50ms
if Date().timeIntervalSince(lastTime) > 0.15 { ... }
fnKeyReleaseTimer = Timer.scheduledTimer(withTimeInterval: 0.05, ...)

// 现在：超时时间50ms，检测间隔20ms
if Date().timeIntervalSince(lastTime) > 0.05 { ... }
fnKeyReleaseTimer = Timer.scheduledTimer(withTimeInterval: 0.02, ...)
```

**效果**：
- FN键释放响应速度提升约3倍（从150ms降到50ms）
- 转录启动更加迅速，用户体验更流畅

### 2. 添加麦克风占用检测

**文件**：`fastv/Services/VoiceInputService.swift`

**改进内容**：
- 添加麦克风可用性检查
- 新增`microphoneInUse`错误类型
- 提供友好的错误提示

**代码变更**：
```swift
// 检查麦克风是否可用（可能被其他应用占用）
let format: AVAudioFormat
do {
    format = inputNode.inputFormat(forBus: 0)
    print("✅ [VoiceInputService] 成功获取音频输入格式")
} catch {
    print("❌ [VoiceInputService] 无法获取音频输入格式，麦克风可能被其他应用占用")
    throw VoiceInputError.microphoneInUse
}
```

**错误提示**：
```
"麦克风正被其他应用使用（如闪电说），请先关闭其他语音输入应用"
```

### 3. 添加冲突提示机制

**文件**：`fastv/fastvApp.swift`

**改进内容**：
- 在录音失败时显示友好的错误提示
- 特别处理麦克风被占用的情况
- 提供解决方案建议

**代码变更**：
```swift
catch VoiceInputError.microphoneInUse {
    print("❌ [fastvApp] 麦克风被占用（可能是闪电说或其他应用）")
    waveformManager.hide()

```

**提示内容**：

```
解决方法：
1. 关闭其他语音输入应用
2. 或使用不同的快捷键避免冲突
3. 或在其他应用不录音时使用本应用
```

### 4. 设置界面优化

**文件**：`fastv/Views/SettingsView.swift`

**改进内容**：
- 在设置界面添加FN键冲突警告
- 提供详细的解决方案说明
- 使用醒目的图标和颜色提示

**显示内容**：

```
• 或错开使用时间
```

## 技术细节

### FN键的特殊性

1. **事件类型**：FN键主要通过`flagsChanged`事件触发，而不是标准的`keyDown`/`keyUp`
2. **keyCode**：FN键的keyCode为`0x3F`（63）
3. **释放检测**：FN键通常不产生keyUp事件，需要通过超时或flagsChanged的变化来检测释放

### 麦克风资源独占

1. **AVAudioEngine**：macOS的音频引擎同时只能被一个应用独占使用
2. **冲突场景**：
   - 应用A正在录音 → 应用B尝试录音 → 失败
   - 应用A和B同时尝试录音 → 先抢到的成功，后到的失败
3. **检测方法**：尝试获取`inputNode.inputFormat(forBus: 0)`，如果失败说明麦克风被占用

### 全局快捷键监听

1. **权限要求**：需要辅助功能权限（Accessibility）
2. **事件监听**：使用`NSEvent.addGlobalMonitorForEvents`
3. **多应用共存**：多个应用可以同时监听同一个快捷键，都会收到事件
4. **无法抢占**：无法强制抢占其他应用的快捷键

## 使用建议

### 推荐配置

1. **避免使用FN键**：
   - 推荐使用 `⌥V`（Option+V）
   - 或使用 `⌘⇧V`（Command+Shift+V）
   - 或使用 `⌃Space`（Control+Space）

2. **如果必须使用FN键**：
   - 确保其他语音输入应用（如闪电说）已关闭
   - 或修改其他应用的快捷键
   - 或在不同场景下使用不同应用

### 故障排查

1. **悬浮条不出现**：
   - 检查是否授予了辅助功能权限
   - 在"系统设置 > 隐私与安全性 > 辅助功能"中确认fastv已勾选

2. **悬浮条出现但无法录音**：
   - 检查是否授予了麦克风权限
   - 在"系统设置 > 隐私与安全性 > 麦克风"中确认fastv已勾选
   - 检查是否有其他应用正在使用麦克风

3. **释放后不转录**：
   - 如果使用FN键，确认超时检测已触发（约50ms）
   - 查看控制台日志，确认是否有错误信息
   - 尝试使用其他快捷键（如⌥V）测试

4. **与闪电说冲突**：
   - 方案1：关闭闪电说
   - 方案2：修改其中一个应用的快捷键
   - 方案3：使用不同的快捷键组合

## 性能优化

1. **响应速度**：FN键释放检测从150ms优化到50ms，提升3倍
2. **CPU占用**：定时器检测间隔从50ms优化到20ms，更及时但CPU占用略增
3. **内存占用**：无明显变化

## 总结

本次修复主要解决了两个核心问题：

1. **FN键释放检测延迟**：通过优化超时机制，将响应速度提升3倍
2. **麦克风资源冲突**：添加检测和友好提示，帮助用户理解和解决冲突

同时提供了详细的使用建议和故障排查指南，提升了整体用户体验。
