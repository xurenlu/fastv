# 会议录音增强功能说明

## 功能概述

针对长时间会议录音的两大核心需求,我们实现了以下增强功能:

### 1. 防止合盖中断录音 ✅

**问题**: 会议录音可能持续1小时以上,笔记本合盖会导致系统睡眠,录音中断。

**解决方案**:
- **系统睡眠/唤醒监听** (`SleepWakeNotifier`)
  - 监听 macOS 系统电源事件
  - 检测睡眠前的询问事件并拒绝睡眠
  - 支持睡眠/唤醒事件回调
  
- **防睡眠断言机制**
  - 录音时自动启用 `IOPMAssertion` 防止系统空闲睡眠
  - 使用 `kIOPMAssertionTypePreventUserIdleSystemSleep` 类型
  - 录音结束后自动释放断言,恢复正常节能

**使用场景**:
- 会议录音中合盖电脑 → 系统拒绝睡眠,继续录音
- 长时间无操作 → 系统不会自动睡眠
- 录音完成后 → 自动恢复节能设置

### 2. 实时增量转写 ✅

**问题**: 1小时会议结束后一次性转写所有内容,等待时间长,崩溃/断电会丢失所有记录。

**解决方案**:

#### 核心组件

1. **静音检测器** (`SilenceDetector`)
   - 实时分析音频电平 (RMS)
   - 滑动窗口平滑处理,避免误判
   - 可配置参数:
     - `silenceThreshold`: 静音阈值 (默认 0.01)
     - `minimumSilenceDuration`: 最短静音时长 (默认 1.5秒)
     - `windowSize`: 滑动窗口大小 (默认 10个采样点)
   - 检测到有效静音段时触发回调

2. **增量转写管理器** (`IncrementalTranscriptionManager`)
   - 管理多个音频段落的转写队列
   - 每个段落独立转写,互不影响
   - 实时拼接已完成的转写文本
   - 提供转写进度统计
   - 支持错误处理和重试

3. **分段录音服务** (`VoiceInputService` 增强)
   - 维护两个缓冲区:
     - `recordedBuffers`: 完整录音数据
     - `segmentBuffers`: 当前段落数据
   - 支持提取当前段落音频 (`extractCurrentSegment()`)
   - 记录段落时间点,便于后续对齐

#### 工作流程

```
录音开始
  ↓
静音检测器持续监听音频电平
  ↓
检测到 1.5秒 以上静音
  ↓
提取当前段落音频 (保留原始录音继续)
  ↓
创建转写任务 (异步执行,不阻塞录音)
  ↓
转写完成 → 实时更新UI显示
  ↓
继续录音,等待下一个静音段
  ↓
录音结束
  ↓
快速转写剩余部分 (已有大部分转写结果)
  ↓
合并所有段落 + 纠错 + AI优化 + 生成摘要
```

#### UI 实时反馈

**录音界面新增**:
- **实时转写区域**: 显示已完成转写的段落
  - 自动滚动显示最新内容
  - 支持文本选择和复制
  - 最大高度 150px,超出可滚动查看
  
- **转写进度提示**: 
  - "已完成 3/5 段" - 实时更新
  - 蓝色边框高亮显示
  - 半透明背景,不遮挡主界面

**优势**:
- ✅ 用户可以实时看到转写内容
- ✅ 确认录音质量和识别准确度
- ✅ 意外中断也能保留已转写部分
- ✅ 结束时几乎无需等待

## 技术实现细节

### 1. 防睡眠实现 (`SleepWakeNotifier.swift`)

```swift
// 注册系统电源通知
IORegisterForSystemPower(...)

// 处理睡眠询问
case kIOMessageCanSystemSleep:
    if isPreventingSleep {
        IOCancelPowerChange(service)  // 拒绝睡眠
    } else {
        IOAllowPowerChange(service)   // 允许睡眠
    }

// 启用防睡眠断言
IOPMAssertionCreateWithName(
    kIOPMAssertionTypePreventUserIdleSystemSleep,
    kIOPMAssertionLevelOn,
    "会议录音中",
    &preventSleepAssertion
)
```

**关键点**:
- 使用 `IOKit` 框架的电源管理 API
- 在录音开始时创建断言,结束时释放
- 监听 `kIOMessageCanSystemSleep` 主动拒绝睡眠
- 监听 `kIOMessageSystemWillSleep` 和 `kIOMessageSystemHasPoweredOn` 处理意外睡眠

### 2. 静音检测实现 (`SilenceDetector.swift`)

```swift
// 处理音频电平
func processAudioLevel(_ level: Float) -> SilenceDetection {
    // 添加到历史记录
    audioLevelHistory.append(level)
    
    // 滑动窗口平均 (平滑处理)
    let averageLevel = audioLevelHistory.reduce(0, +) / Float(count)
    
    // 判断是否静音
    if averageLevel < silenceThreshold {
        // 计算静音持续时长
        let duration = Date().timeIntervalSince(silenceStartTime)
        
        // 达到最小时长 → 触发回调
        if duration >= minimumSilenceDuration {
            onSilenceDetected?(duration)
        }
    }
}
```

**关键点**:
- 滑动窗口避免瞬时噪音误判
- 持续时长判断避免短暂停顿
- 只触发一次回调 (容差 200ms)

**关键点**:
- 每个段落独立异步转写
- 不阻塞主线程和录音
- 支持错误恢复
- 按时间顺序拼接结果

## 配置参数

### 静音检测参数 (可在 `SilenceDetector` 中调整)

```swift
var silenceThreshold: Float = 0.01        // RMS阈值 (0-1)
var minimumSilenceDuration: TimeInterval = 1.5  // 最短静音时长(秒)
var windowSize: Int = 10                  // 滑动窗口大小
```

**调优建议**:
- 安静环境: `silenceThreshold = 0.005`, 更灵敏
- 嘈杂环境: `silenceThreshold = 0.02`, 降低误判
- 快速对话: `minimumSilenceDuration = 1.0`, 更频繁切分
- 慢速演讲: `minimumSilenceDuration = 2.0`, 更长段落

### 分段时长限制 (`IncrementalTranscriptionManager`)

```swift
private let minimumSegmentDuration: TimeInterval = 3.0   // 最短段落
private let maximumSegmentDuration: TimeInterval = 60.0  // 最长段落
```

**建议值**:
- 最短: 3-5秒 (避免过于频繁转写)
- 最长: 60-120秒 (避免单次转写时间过长)

## 性能影响

### 内存占用

**原方案** (一次性转写):
- 1小时录音: ~230 MB RAM (16kHz 单声道)
- 峰值内存: 转写时 +200 MB

**新方案** (增量转写):
- 1小时录音: ~230 MB RAM (完整录音仍需保留)
- 峰值内存: 每段转写 ~20-40 MB (5-10秒段落)
- 优势: 分段转写,内存压力分散

### CPU 占用

**转写任务**:
- 原方案: 结束时集中 CPU 密集计算
- 新方案: 分散到录音过程中,平滑 CPU 占用

**静音检测**:
- 开销极小: 每 50ms 一次简单 RMS 计算
- 滑动窗口: 10个浮点数的平均值
- 几乎可忽略

### 电池消耗

**防睡眠断言**:
- 阻止系统睡眠 → 持续耗电
- 建议: 长会议时接通电源

**增量转写**:
- 分散计算 vs 集中计算
- 总能耗相近,体验更好

## 使用建议

### 长时间会议 (>1小时)

1. **接通电源**: 防睡眠会持续耗电
2. **保持唤醒**: 虽然有防睡眠,但最好不合盖
3. **监控实时转写**: 确认识别质量
4. **安静环境**: 减少背景噪音,提高准确度

### 环境配置

1. **调整静音阈值**: 根据环境噪音调整
2. **检查防睡眠**: 录音时状态栏应显示防睡眠图标
3. **网络稳定**: AI优化需要网络连接

### 故障恢复

**如果意外中断**:
- ✅ 已转写的段落已保存在 `incrementalTranscription`
- ✅ 可以导出部分结果 (未来可增加自动保存)
- ❌ 未转写的最后一段会丢失

**建议**: 后续可增加定期保存到磁盘的功能
