# 语音输入文本插入修复说明

## 🐛 问题描述

用户反馈在使用AI语音输入法时，输入的文本前面会莫名其妙地插入一些之前复制过的内容。例如：

- 用户说了20个字
- 但实际插入的内容前面多了一些其他内容
- 这些内容可能是之前复制的文字

这个问题严重影响用户体验，导致软件无法正常使用。

## 🔍 问题原因

问题出在 `TextInsertionService.swift` 的剪贴板恢复逻辑中：

### 原有代码逻辑

```swift
func insertText(_ text: String) {
    // 1. 保存当前剪贴板内容
    let previousContents = pasteboard.string(forType: .string)
    
    // 2. 设置新的剪贴板内容
    pasteboard.setString(text, forType: .string)
    
    // 3. 模拟 Cmd+V 粘贴
    // ... 发送按键事件 ...
    
    // 4. 0.1秒后恢复原来的剪贴板内容 ← 问题所在！
    DispatchQueue.main.asyncAfter(deadline: .now() + 0.1) {
        if let previousContents = previousContents {
            pasteboard.setString(previousContents, forType: .string)
        }
    }
}
```

### 竞态条件分析

```
时间线:
0ms    - 设置剪贴板为"语音输入内容"
1ms    - 发送 Cmd+V 按键事件
100ms  - 恢复剪贴板为"旧内容"  ← 太早了！
???ms  - 目标应用处理粘贴事件  ← 可能在100ms之后！
```

**问题**：
1. 不同应用处理粘贴事件的速度不同
2. 有些应用可能需要超过100ms才能处理粘贴
3. 如果应用在100ms后才读取剪贴板，就会读到**恢复后的旧内容**
4. 导致用户看到旧内容被插入

### 为什么会出现"前面多了内容"？

这可能是因为：
1. 用户之前复制过一些文本（存在剪贴板中）
2. 语音输入时，新内容被设置到剪贴板
3. 100ms后，剪贴板被恢复为旧内容
4. 目标应用读取剪贴板时，可能读到：
   - 部分新内容 + 部分旧内容（如果应用分多次读取）
   - 完全是旧内容（如果应用延迟读取）

## ✅ 修复方案

### 核心改动

**不再恢复剪贴板内容**

理由：
1. 用户语音输入的内容比剪贴板原有内容更重要
2. 恢复操作会导致不可预测的竞态条件
3. 如果用户需要原有内容，可以使用撤销功能

### 新增保护机制

```swift
class TextInsertionService {
    // 1. 标记是否正在插入
    private var isInserting = false
    
    // 2. 串行队列确保顺序执行
    private let insertionQueue = DispatchQueue(label: "com.fastv.textInsertion")
    
    func insertText(_ text: String) {
        insertionQueue.async {
            // 3. 等待之前的插入完成
            while self.isInserting {
                Thread.sleep(forTimeInterval: 0.01)
            }
            
            self.isInserting = true
            
            // 4. 在主线程执行插入
            DispatchQueue.main.sync {
                self.performTextInsertion(text)
            }
            
            // 5. 等待足够时间确保粘贴完成
            Thread.sleep(forTimeInterval: 0.3)
            
            self.isInserting = false
        }
    }
}
```

### 新增验证机制

```swift
private func performTextInsertion(_ text: String) {
    // 设置剪贴板
    pasteboard.setString(text, forType: .string)
    
    // 验证剪贴板内容
    if let clipboardContent = pasteboard.string(forType: .string) {
        if clipboardContent != text {
            print("⚠️ 剪贴板内容不匹配！")
        }
    }
    
    // 发送粘贴命令...
}
```

### 新增按键间延迟

```swift

```

## 🔧 技术细节

### 为什么不恢复剪贴板？

1. **无法确定恢复时机**
   - 不同应用处理粘贴的速度不同
   - 无法知道目标应用何时完成读取

2. **用户体验优先**
   - 语音输入的内容是用户当前需要的
   - 剪贴板原有内容可以通过其他方式获取

3. **简化逻辑**
   - 减少竞态条件
   - 代码更可靠

### 串行队列的作用

```
用户快速连续语音输入:
  输入1 → 队列 → 执行 → 完成
  输入2 → 队列 → 等待 → 执行 → 完成
  输入3 → 队列 → 等待 → 等待 → 执行 → 完成
```

确保每次输入都完整执行，不会互相干扰。

## ⚠️ 注意事项

### 剪贴板内容会被覆盖

修复后，语音输入会覆盖剪贴板原有内容。如果用户之前复制了重要内容：
- 使用语音输入后，原内容会丢失
- 建议用户在语音输入前确认剪贴板内容不重要

### 输入间隔

连续语音输入之间会有约300ms的间隔，这是为了确保：
- 前一次粘贴完全完成
- 剪贴板状态稳定
- 目标应用已处理完毕
