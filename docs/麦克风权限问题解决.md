# 麦克风权限问题解决指南

## 🔍 问题诊断

从你的日志中发现了问题：

```
🎤 [VoiceInputService] 麦克风权限状态: 2
❌ [VoiceInputService] 麦克风权限未授权，抛出错误
```

**状态码 2 = `.denied`**，表示麦克风权限被拒绝了！

## ✅ 解决步骤

### 方法1：通过应用提示（推荐）⭐

1. **重新编译运行应用**（已编译成功）
2. **按下Control键**触发语音输入
3. **会弹出权限提示对话框**：
   ```
   需要麦克风权限
   
   语音输入功能需要访问麦克风。
   
   请按以下步骤授权：
   1. 打开"系统设置"
   2. 进入"隐私与安全性" > "麦克风"
   3. 找到 fastv 并勾选
   4. 重新尝试语音输入
   ```
4. **点击"打开系统设置"**按钮
5. 系统会自动跳转到麦克风权限页面
6. **找到 fastv 并勾选**
7. **重新尝试语音输入**

### 方法2：手动设置

1. 打开"系统设置"（System Settings）
2. 点击"隐私与安全性"（Privacy & Security）
3. 点击"麦克风"（Microphone）
4. 在应用列表中找到"fastv"
5. 勾选 fastv 旁边的复选框
6. 关闭设置窗口
7. 重新尝试语音输入

### 方法3：命令行重置（如果上述方法不行）

```bash
# 重置麦克风权限（需要重启应用）
tccutil reset Microphone com.wxside.fastv
```

然后重新打开应用，会再次请求麦克风权限。

## 🎯 验证权限

### 检查权限状态

重新运行应用后，查看日志应该显示：

```
🎤 [VoiceInputService] 麦克风权限状态: 3 (已授权)
✅ [VoiceInputService] 麦克风权限已授权，继续录音设置
```

**状态码说明**：
- `0` = 未确定（notDetermined）
- `1` = 受限制（restricted）
- `2` = 已拒绝（denied）⚠️
- `3` = 已授权（authorized）✅

### 测试录音

1. 按下Control键
2. 应该看到：
   ```
   ✅ [VoiceInputService] 录音已开始
   📊 [WaveformWindowManager] 波形窗口已显示
   ```
3. 说话，观察波形动画
4. 松开Control键
5. 等待转录完成

## 🐛 其他发现的问题

### 问题1：窗口显示时机

**现象**：窗口在异步显示完成前就被关闭了

**修复**：改为同步显示窗口
```swift
// 之前：异步显示（太慢）
DispatchQueue.main.async {
    window.orderFrontRegardless()
}

// 现在：同步显示（立即）
window.orderFrontRegardless()
window.makeKeyAndOrderFront(nil)
```

### 问题2：权限错误提示不明确

**修复**：
- 添加了详细的权限状态描述
- 添加了专门的权限提示对话框
- 提供"打开系统设置"按钮，一键跳转

## 💡 常见问题

### Q1: 为什么之前没有请求权限？

**答**：可能是：
1. 第一次运行时点击了"拒绝"
2. 系统设置中手动关闭了权限
3. 其他原因导致权限被撤销

### Q2: 授权后还是不行？

**答**：尝试：
1. 完全退出应用（Command+Q）
2. 重新打开应用
3. 再次测试

### Q3: 测试按钮能看到窗口，但快捷键不行？

**答**：这是因为：
- 测试按钮不需要麦克风权限（只显示窗口）
- 快捷键会触发录音（需要麦克风权限）
- 录音失败后窗口会立即关闭

### Q4: 系统设置中没有 fastv？

**答**：
1. 确保应用至少运行过一次
2. 尝试重新编译运行
3. 或使用命令行重置：`tccutil reset Microphone`
