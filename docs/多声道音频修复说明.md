# 多声道音频处理修复说明

## 🐛 问题描述

当视频文件包含多个音频轨道（例如2个声道）时，之前的代码只处理了第一个音频轨道，导致：
- 丢失其他声道的信息
- 如果第一个声道是静音或背景音，无法提取到人声
- 提取不到字幕或提取结果不完整

## ✅ 修复内容

### 修改文件
- `fastv/Services/SpeechTranscriber.swift` - `preprocessAudio` 函数

### 修复前的问题
```swift
// ❌ 只取第一个音频轨道
guard let audioTrack = try await asset.loadTracks(withMediaType: .audio).first else {
    throw VideoProcessingError.noAudioTrack
}
```

### 修复后的改进
```swift
// ✅ 获取所有音频轨道
let audioTracks = try await asset.loadTracks(withMediaType: .audio)
guard !audioTracks.isEmpty else {
    throw VideoProcessingError.noAudioTrack
}

// ✅ 将所有音频轨道添加到 composition
for audioTrack in audioTracks {
    // ... 添加到 composition
}
```

## 🔧 工作原理

1. **获取所有音频轨道**：不再只取第一个，而是获取所有音频轨道
2. **添加到 Composition**：将所有轨道添加到 `AVMutableComposition`
3. **自动混合**：`AVAssetReaderAudioMixOutput` 会自动将所有轨道混合成单声道
4. **转换为 16kHz 单声道**：最终输出符合 SenseVoice 模型要求的格式

## 📝 注意事项

1. **性能影响**：处理多个轨道可能会稍微增加处理时间，但影响很小
2. **内存使用**：所有轨道都会被加载到内存，对于非常大的文件需要注意
3. **自动混合**：`AVAssetReaderAudioMixOutput` 会自动混合所有轨道，无需手动处理

## 💡 如果仍然无法提取字幕

如果修复后仍然无法提取字幕，可能的原因：

1. **音频质量问题**：
   - 音频太安静或噪音太大
   - 人声被背景音乐掩盖

2. **模型问题**：
   - ONNX Runtime 未正确集成
   - 模型文件损坏或路径错误

3. **特征提取问题**：
   - 音频预处理失败
   - CMVN 文件未找到或格式错误

**调试步骤**：
1. 检查控制台输出的调试信息
2. 确认音频轨道数量是否正确
3. 检查音频样本统计信息（RMS、min、max 等）
4. 确认特征提取是否成功
